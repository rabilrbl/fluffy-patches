# 👋 Contribution guidelines

This document describes how to contribute to Fluffy Patches.

## 📖 Resources to help you get started

* [Issues](https://github.com/rabilrbl/fluffy-patches/issues) are where we keep track of bugs and feature requests
* See [docs/](docs/) for APK analysis notes on the supported apps

## 🙏 Submitting a feature request

Features can be requested by opening an issue using the
[Feature request issue template](https://github.com/rabilrbl/fluffy-patches/issues/new?labels=Feature+request&template=feature_request.yml&title=feat%3A+).

## 🐞 Submitting a bug report

If you encounter a bug while using Fluffy Patches, open an issue using the
[Bug report issue template](https://github.com/rabilrbl/fluffy-patches/issues/new?labels=Bug+report&template=bug_report.yml&title=bug%3A+).

## 📝 How to contribute

1. Before contributing, it is recommended to open an issue to discuss your change
with the maintainers of Fluffy Patches
2. Development happens on the `dev` branch. Fork the repository and create your branch from `dev`
3. Commit your changes using [conventional commit](https://kapeli.com/cheat_sheets/Semantic_Commits.docset/Contents/Resources/Documents/index) messages (`feat:`, `fix:`, `chore:`)
4. Submit a pull request to the `dev` branch of the repository and reference issues
that your pull request closes in the description of your pull request
5. Your pull request will be reviewed and, once approved,
merged into the `dev` branch and included in the next release of Fluffy Patches

❤️ Thank you for considering contributing to Fluffy Patches
